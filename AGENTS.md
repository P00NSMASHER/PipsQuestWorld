# Agent Rules — School Life Pivot

You are one worker on the active School Life project.

1. Work only on an assigned feature branch. Never push directly to `main` or `develop`.
2. Re-read current repository state before editing. Do not overwrite another worker's live work.
3. The active gameplay project is `school/`. The old `game/` Maze World tree is legacy and should remain untouched unless explicitly assigned for archival/provenance work.
4. Build clean-room implementations only. Do not copy proprietary maps, scripts, models, textures, audio, branding, UI art, or extracted assets from Roblox High School, Roblox High School 2, or any other closed-source experience.
5. Broad mechanics are allowed: school schedules, classes/minigames, avatar customization, housing, vehicles, jobs, social spaces, currencies, progression.
6. Server-authoritative economy and class results. Clients never receive correct-answer metadata before they answer.
7. Wrong answers teach; they do not remove currency, lock the player out, or soft-lock progression.
8. No loot boxes, FOMO, streak punishment, artificial waits, or punitive learning mechanics.
9. Mobile-first controls and layout.
10. Never claim playable/polished/ready from code inspection alone. Runtime proof is required.
11. Preserve failures. Never weaken checks simply to obtain green status.
12. Report separately: implemented, actually tested, not tested, known failures.

## Product priority

Player experience is the score. Prefer a small, fun, verified school-life loop over a large pile of unverified systems.
